# 舰桥 0.1.4

本版修复连接记录混淆上游生成结果与本地接收结果的问题，并更新界面字标和透明图标。

## 连接记录

- 上游已返回完成事件后，原生 Responses 流立即正常结束，不再等待连接关闭后被尾部断线误记为失败。
- Chat 流已返回 `finish_reason` 时，尾部网络断线不会抹掉已完成的生成结果；仍保留已收到的用量和尾部断线说明。上游明确返回的错误仍会记录。
- 分开显示成功、上游失败、处理异常、连接中断、超时、已取消和输出未完成。长度截断不再显示成完整成功。
- 详情分别显示本地结果和上游结果，并记录收到的 HTTP 状态、上游请求 ID、异常阶段及可用的网络错误码。
- 用量未知时显示「—」；已在响应中收到的用量会在中断或失败时保留。
- 「成功率」改为「响应完成率」，排除取消请求，并说明该指标基于本地请求尝试。重试分别计数。
- CSV 使用与界面相同的分类和未知值语义。

历史记录里的 `fetch failed` 只能说明舰桥没有完整收到响应，不能证明模型生成失败。新版在读取时将这类旧记录显示为连接中断，并明确上游结果未知；不会重写原始历史记录或补造 HTTP 状态。没有增加自动生成重试。

## Logo

界面使用完整「舰桥 FLEET BRIDGE」字标，裁去透明空白，保留原有颜色与比例。深色主题提供浅色底面，小窗口约束字标边界。任务栏、托盘与程序文件采用 512px 透明图标，ICO 包含 16–256px 多种尺寸。

## 验证

使用隔离的应用数据和 Codex 配置进行验证，上游由本地模拟服务提供，不发送付费 API 请求。自动化覆盖协议完成、流中断、超时、主动取消、明确上游错误、转换异常、历史兼容、界面与 CSV；另使用 Codex 执行模型列表、推理强度与文件编辑回归。运行测试时生成的结果位于 `artifacts/`，不随源码提交。

本版改善错误归因与记录准确性；真实网络中断仍需结合新记录中的错误码和上游请求 ID 排查。

## 更新

在托盘菜单中选择「退出舰桥」，再运行 `Fleet-Bridge-0.1.4-Windows.exe`。旧版没有完全退出时，单实例机制可能仍显示旧窗口。已保存的服务商、密钥、模型配置和连接记录继续使用。
